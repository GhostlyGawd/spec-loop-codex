# Operations plan

## Service and owners
State the main user journeys, owners, support path, dependencies, and environments.

## Signals
For each service or product signal: source, definition, window, target, alert threshold, owner, and response. Include reliability, latency, failures, cost, and product value where relevant.

## Runbooks
Define diagnosis, safe containment, recovery, verification, escalation, and the authority needed. Include failed jobs, external provider failure, capacity, and data recovery where relevant.

## Data and maintenance
State backup and restore checks, retention, deletion, dependency review, credential rotation, feature flag removal, and cost review. Use cadences only when justified.

## Incidents
Record ID, time, impact, evidence, actions, actual recovery, contributing causes, detection gaps, and follow-up change IDs.

## Scheduling status
Distinguish proposed cadence from an actual scheduled task. For a created schedule, record its real ID and status.
