# Product design

## User task and approach
Link the brief and requirement IDs. Compare meaningful options when needed. State the selected approach and why it fits the user.

## Journey
Describe entry, main steps, success, alternative paths, cancellation, and recovery. Define navigation and information hierarchy.

## States
For each relevant screen or interaction, specify empty, loading, success, error, partial failure, offline, denied access, and expired session behavior. Define inputs, validation, feedback, and content.

## Visual and interaction rules
State component reuse, layout, spacing, type, color, focus, motion, responsive behavior, and device needs. Include localization and accessibility needs. For an API or CLI, use its request or command contract.

## Validation
Link prototypes or actual artifacts. Record who completed which task, observed problems, accessibility checks, and limitations. Separate an agent review from a real user test.

## Acceptance links
Map requirement and criterion IDs to the selected behavior and planned checks.
