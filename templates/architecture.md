# Architecture and data

## Context
Link requirements and quality targets. Describe the current baseline and constraints.

## Boundaries
Define components, ownership, data flow, trust boundaries, external services, and failure domains.

## Data and contracts
Define entities, keys, invariants, sensitivity, access, retention, export, and deletion. Link API and event schemas. State versioning, errors, timeouts, retries, idempotency, and concurrency.

## Quality
For performance, reliability, recovery, cost, and capacity, state the workload, target, method, and owner. Label assumed values.

## Decisions
For each major choice: stable ID, context, viable options, decision, reason, consequences, validation, and review trigger.

## Migration and recovery
State order, mixed version compatibility, backfill, integrity checks, lock risks, rollback or forward repair, backup, restore, and rehearsal.

## Security and AI
Link the threat review. For AI behavior, state model and prompt versions, input limits, allowed actions, evaluation set, fallback, latency, cost, and review needs.

## Open questions
Record uncertainty, impact, owner, and the next test that can resolve it.
