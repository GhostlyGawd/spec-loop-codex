# Product design

Read the shared protocol and the approved brief. Use the [design template](../../../templates/design.md). Preserve existing brand and component rules.

Map the main task from entry to successful completion. Include alternative and recovery paths. Explore different approaches when the interaction is uncertain; state the selected option and its reason. Use a prototype or visual reference when it resolves a real design question.

Specify navigation, content, information hierarchy, component states, input rules, and feedback. Check empty, loading, success, error, partial failure, offline, denied access, and expired session states when applicable. Define responsive behavior and keyboard focus. Add localization and assistive technology needs for the target audience.

For nonvisual products, use the appropriate contract: CLI inputs and exit codes, API requests and errors, data product quality and lineage, or device permissions and interactions.

Validate the main journey through actual interaction where possible. Include wrong input, interrupted work, and recovery. Use real users to test demand and usability when available. Label an agent walkthrough as a design review. Automated accessibility checks do not replace keyboard and relevant assistive technology checks.

Output the selected design, complete behavior states, unresolved questions, and checks linked to acceptance criteria. Avoid implementation details in product UI unless the user needs them to make a decision.
