# Operate and maintain

For product goals, priorities, linked scope, and current roadmap facts, use [the product workflow](product.md). Read it when product state exists or this stage changes a product decision.
Read the shared protocol and the [operations template](../../../templates/operations.md). Start from observed service state and current product usage.

Connect the main user journey to service signals, logs, metrics, traces, cost, and support. Define owners, measurement windows, thresholds, alert actions, and retention. Check backups by restore when needed. Review dependency vulnerabilities, credentials, queued jobs, feature flags, and cost based on actual exposure.

For an incident, identify scope and severity, preserve useful evidence, and contain impact within existing authority. Use a compact emergency contract. Restore service and check the user journey. Do not delay urgent authorized recovery to complete routine discovery documents.

After recovery, link the incident to the failed assumption or control, detection gap, corrective change, and follow-up owner. Record what is known and what remains uncertain. Draft external updates only unless sending is authorized.

For recurring maintenance, use an available scheduling tool and verify creation if the user requested a schedule. A plan that says “weekly” is not a scheduled task. Avoid background service claims when the plugin is only operating in the current conversation.

Output current health, evidence, actions completed, open risks, and the next maintenance or product change.
